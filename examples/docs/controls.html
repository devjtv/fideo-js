Interface

Controls & keyboard

One control bar for every provider, rendered inside a shadow root so page CSS cannot break it and its own styles cannot leak out.

Click the video, then try the shortcuts below—

Anatomy

ControlBehaviour
Play / pauseIcon and label follow playback state.
Elapsed / durationTabular figures, so the bar does not jitter as digits change. Switches to h:mm:ss past an hour.
TimelineA range input. Shows played, buffered and remaining as three bands; interpolates between updates so it moves smoothly.
VolumeMute toggle that reveals a vertical slider on hover or focus. Dragging to zero mutes; unmuting restores the last audible level.
SettingsPlayback-rate menu. The active rate is ticked and exposed as aria-checked.
FullscreenRequests fullscreen on the wrapper, so posters, overlays and controls all scale with it.
Only HTML5 reports a buffered range. The band is there for every provider, but iframe providers report zero, so it stays empty. See capability differences.

Keyboard

A transparent button covers the video surface. It is the click-to-play target and the shortcut host, so shortcuts work once a player has focus and never hijack keys while the visitor is typing elsewhere on the page.

Space / EnterPlay or pause
← / →Seek 5 seconds, clamped to the duration
↑ / ↓Volume by 10%. ↑ also unmutes.

Esc closes the volume panel too, returning focus to the mute button.

When the bar is visible

The control bar fades in on any of these, and fades out again shortly after activity stops during playback.

  • Pointer over the player
  • Focus anywhere inside it, so keyboard users never lose the controls
  • While paused — a paused player keeps its controls up
  • For about 1.8 seconds after a shortcut or a click
Visibility is driven by classes on the wrapper — is-playing, is-paused, is-user-active, has-poster, is-poster-visible, is-fullscreen. Hook your own CSS onto them, or force the bar open in a demo by adding is-user-active.

Hiding controls

Drop individual controls, or the whole bar. Hidden controls are never created, not merely hidden with CSS.

Play, elapsed time, timeline and fullscreen only3 controls removed
The markup abovehtml
<video
  data-fideo
  data-fideo-show-settings="false"
  data-fideo-show-volume="false"
  data-fideo-show-duration="false"
></video>
No control bar at allhtml
<video data-fideo data-fideo-controls="false"></video>
controls: false also removes the click target. With no control bar there is no click-to-play and no keyboard shortcuts, so drive the player from your own UI through the JavaScript API.

Accessibility

  • Every control is a real button or range input with an accessible name, reachable by keyboard in DOM order.
  • The timeline exposes aria-valuetext as "elapsed of duration", updated once per second rather than every frame so screen readers are not flooded.
  • The mute button carries aria-pressed; the settings menu uses menuitemradio with aria-checked on the active rate.
  • The click target has a visible focus ring drawn in the player's accent colour.
  • Timeline interpolation is skipped when prefers-reduced-motion: reduce is set.
Captions are not part of the control bar yet. Native <track> elements still work on an HTML5 player, and providers keep their own caption handling, but Fideo does not render a caption toggle.
