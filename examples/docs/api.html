JavaScript API

Every entry point returns the same player instance, and every provider implements the same methods. Code written against an MP4 works unchanged against a YouTube embed.

Methods

All the playback methods return a promise. For iframe providers that promise also covers loading the SDK, so awaiting play() on a lazy embed waits for it to be ready.

MethodReturnsNotes
play()Promise<void>May reject when browser autoplay policy blocks it — catch it.
pause()Promise<void>
seek(seconds)Promise<void>Absolute position in seconds.
setVolume(value)Promise<void>0–1, clamped.
setMuted(muted)Promise<void>
setPlaybackRate(rate)Promise<void>Providers may refuse unusual rates.
setSource(url)Promise<void>Swaps the media in place. See below.
getState()FideoStateSynchronous snapshot — a copy, not a live object.
destroy()voidFull teardown. Safe to call twice.
Typical usejs
const player = new Fideo('#hero', { muted: true });

await player.play().catch(() => {
  // Autoplay was blocked — show your own play affordance.
});

await player.seek(30);
await player.setVolume(0.4);

setSource()

  • HTML5 replaces src and reloads, resuming playback if it was playing. Setting the URL it already has is a no-op.
  • YouTube and Vimeo load the new video through their APIs, so the iframe is not recreated. The URL is normalized first.
  • Wistia swaps the media ID on the custom element.
Responsive sources can overwrite it. If the player has sources configured, a resize that crosses a breakpoint reapplies the matching source and discards what you set.

Events

Every player dispatches namespaced CustomEvents on its media element. They bubble, so one listener on a container can serve a whole page of players.

EventFires when
fideo:playPlayback starts or resumes
fideo:pausePlayback pauses
fideo:endedPlayback reaches the end
fideo:timeupdatePosition advances
fideo:volumechangeVolume or muted state changes
fideo:changeAny other state change, such as duration becoming known
detail carries the player and a state snapshotjs
player.element.addEventListener('fideo:timeupdate', (event) => {
  const { player, state } = event.detail;
  if (state.duration && state.currentTime / state.duration > 0.9) {
    markAsWatched(player.element.id);
  }
});

// Or once, for every player on the page
document.addEventListener('fideo:play', (event) => {
  analytics('video_play', { id: event.target.id });
});
Listen on the element, not the wrapper. Events are dispatched from player.element and bubble upward from there.

Adapter events

The adapter is an EventTarget emitting un-namespaced versions of the same events, plus durationchange. It is what the control bar listens to. Reach for it only when you need something the player API does not expose — it is closer to the provider and less stable.

Lower leveljs
player.adapter.addEventListener('durationchange', () => {
  console.log(player.getState().duration);
});

Teardown

destroy() is thorough, which is what makes remounting safe:

  • Listeners are removed through AbortControllers, and observers disconnect.
  • The control bar, poster overlay and click target are removed.
  • The element leaves the wrapper and returns to its original position, and the wrapper is deleted.
  • State classes and data-fideo-ready are cleared.
  • The instance is released, so a later mountFideo() creates a fresh one.
A wrapper you wrote yourself is removed too. If the element was already inside an element with class fideo, Fideo adopts it rather than creating one — and destroy() then removes your markup. Let Fideo create its own wrapper.
